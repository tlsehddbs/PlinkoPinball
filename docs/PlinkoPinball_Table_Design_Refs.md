- 향후 제작할 **트리거/이벤트/모듈 슬롯 기반 로드맵**을 구체화한다.

## 1) 핀볼 테이블을 구성하는 요소 요약 (무슨 기능으로 작동하는가)

아래 요소들은 “공이 **부딪히거나(Hit)**, **지나가거나(Pass)**, **상태가 바뀌거나(Switch/Collect)**, **특정 영역에 들어가거나(Zone)**” 하는 순간을 감지해서
점수/배수/모드/보상(시간/코인)을 발생시키는 장치들이다.

### A. Hit(충돌) 기반 요소

1. **Pop Bumper (팝 범퍼)**
   - 작동: 충돌 → 강한 반발 + 점수/누적
   - 특징: 히트가 잦아서 “작은 점수 빠르게 쌓기”에 최적
2. **Slingshot (슬링샷)**
   - 작동: 특정 고무 구간 충돌 → 옆으로 튕김 + 점수
   - 특징: 하단에서 공이 오래 살아남도록 ‘리듬’ 생성
3. **Standup Target (스탠드업 타겟)**
   - 작동: 맞추면 스위치 ON(즉시 복귀) + 점수/조건 진행
   - 특징: “N개 맞추면 모드” 같은 목표 설계에 유리
4. **Drop Target (드롭 타겟)**
   - 작동: 맞추면 내려가서 비활성(‘수집’) + 점수/세트 보상
   - 특징: 세트 완성 보너스(배수/게이트 충전) 설계에 강함

### B. Pass(통과) 기반 요소

5. **Rollover Lane / Inlane / Outlane (레인/인·아웃레인)**
   - 작동: 공이 지나감(Trigger) → 점수/배수/보너스/페널티
   - 특징: “경로 선택”이 곧 점수 전략이 된다.
6. **Orbit / Loop (오빗/루프)**
   - 작동: 바깥 라인을 한 바퀴 돌아 ‘샷 성공’ 취급 → 보상 큼
   - 특징: 고속 구간. 배수/모드 진입과 잘 어울림.
7. **Ramp (램프)**
   - 작동: 경사 통로 성공 → 큰 보상/모드 진입/보너스 장전
   - 특징: ‘샷’의 대표. 성공감/연출 포인트.

### C. “모드/전환” 기반 요소

8. **Scoop / Hole / Saucer (스쿱/홀/소서)**
   - 작동: 공이 “먹힘” → 정지 → 보상 지급/선택/모드 시작 후 배출
   - 특징: “웜홀 진입” 같은 전환 포인트로 최적
9. **Kicker / VUK (키커/버티컬 업키커)**
   - 작동: 공을 다른 위치로 강제 발사(텔레포트 느낌)
   - 특징: 보너스룸/서브루프 연결에 좋음

## 2) 우리 게임에 적용할 수 있는 방식 (예시)

### 2.1 기본 점수 철학

- **baseValue는 작고(1~10), 이벤트 빈도는 높게** 설계
- “폭발감”은 **배수/보너스 구간/업그레이드**로 만든다
- 예: 범퍼 3점, 스피너틱 1점, 램프 성공 10점

### 2.2 TableEvent 예시(아이디/타입/기본값/태그)

- `bumper_small_hit` / Hit / 3 / score
- `sling_left_hit` / Hit / 2 / score
- `pin_plinko_hit` / Hit / 1 / score,bonus
- `lane_left_pass` / Pass / 4 / score,gate
- `orbit_right_pass` / Pass / 6 / score,gate
- `scoop_wormhole_enter` / Zone / 0 / bonus (모드 전환 트리거)
- `outlane_left_pass` / Pass / 0 / timePenalty (위험 레인)

### 2.3 업그레이드와 연결(예시)

- “플링코 핀 점수 +20%” → `eventId == pin_plinko_hit`에만 가산/곱 적용
- “레인 통과 시 게이트 충전 +50%” → `tags contains gate`인 이벤트에만 적용
- “보너스룸 배수 +0.5” → 보너스 상태에서만 multiplier 증가

## 3) 모듈로 구성하는 방법 (예시 6개)

### 모듈 예시 1) Pop Bumper 클러스터 모듈

- 팝 범퍼 3개 + 슬링샷 1개 → 잦은 히트로 점수 누적

### 모듈 예시 2) Spinner 게이트 모듈

- 스피너 1개 + 짧은 레인 → ‘틱’ 연타 + 게이트 충전

### 모듈 예시 3) Drop Target 세트 모듈

- 드롭 타겟 3~5개 → 세트 완성 보상(배수/게이트/모드)

### 모듈 예시 4) Orbit/Ramp 미니샷 모듈

- 좌/우 루프 또는 짧은 램프 → 샷 성공 고보상

### 모듈 예시 5) 위험/보상 레인 모듈

- Outlane 위험 통로 + 구제(세이브) 스위치 → 리스크-리턴

### 모듈 예시 6) Wormhole Scoop 모듈

- 스쿱 1개 + 충전 조건 → 보너스룸 전환 트리거

## 4) 예상되는 테이블 구성

### 4.1 좌표 / 비율 가정

- 테이블 비율: **가로 1 : 세로 1.5**
- 월드 좌표: 아래쪽(플레이어) = -Z, 위쪽 = +Z, 런치 레인 = +X

### 4.2 구역을 5개로 나누기

1) 하단: 플리퍼/슬링샷/인·아웃레인/드레인  
2) 중앙: 타겟/스위치/게이트 충전  
3) 상단: 팝범퍼/핀 클러스터(점수 누적)  
4) 좌우 외곽: 오빗/루프/램프 경로(샷)  
5) 전환: 웜홀 스쿱(보너스룸 진입)

### 4.3 배치 상세

- **런치 레인(+X)**: 스폰(-Z 하단) → 레인 위(+Z)로 발사 → 본판 합류
- **하단(-Z)**: 좌/우 플리퍼 + 슬링샷, 인레인은 작은 보상/세이브, 아웃레인은 시간 페널티
- **중앙(0 부근)**: 스탠드업 타겟 3개(게이트 충전), 드롭타겟 3~5개(세트 보상)
- **상단(+Z)**: 팝범퍼 3개 삼각 배치(난반사로 오래 머무름)
- **외곽(-X/+X)**: 오빗/루프 통로로 ‘샷 성공’ 보상
- **웜홀 스쿱(+Z, +X 근처)**: 게이트가 차면 진입 가능 → 보너스룸 전환

## 5) 제작 시 라이선스/저작권/상표 리스크(요약)

- **핀볼 장르/일반적인 메커니즘(Hit/Pass/레인/범퍼/플리퍼)** 자체는 보통 ‘아이디어/기능’ 범주라 그대로 구현해도 문제될 가능성이 낮다.
- 다만 **특정 게임(예: Space Cadet) 테이블 레이아웃, 아트/사운드, 명칭, 룰 문구**를 그대로 복제하면 위험.
- 유명 실물 테이블의 **테마/IP/로고/캐릭터/음악/테이블명**도 사용 금지(별도 라이선스 필요 가능).
